> 工作名 LeanFPS（`leanfps.com` 2026-10-09 在 Verisign RDAP 查询为未注册；备选 `fpslift.com`、`tunedframe.com`）。名字和域名由用户购买后定稿。

## 1. 目标（用户 2026-10-09 的要求）

1. **性能极致**：软件本身轻（体积、内存、CPU 几乎为零），优化项有真实机制。
2. **小窗口**，打开就能看到优化项。
3. 优化项**有默认配置**，用户可以逐项手动调。
4. **识别正在运行的游戏并显示图标**。
5. **识别游戏类型，做专项优化**，让用户看到「识别到了这个游戏、为它做了哪些优化」。
6. 安装包 < 20 MB（我们的目标是 < 8 MB）。
7. 售价 **$19 一次买断**；下载、首次使用、购买流程要顺。
8. 其他参考同类方案，由 Agent 决定。

## 2. 关键决定（Agent 已定，理由在后）

| 项 | 决定 |
| --- | --- |
| 语言 / UI | 纯 Rust；界面用 **egui（eframe + glow 渲染）**。单个 exe、无 WebView2/.NET 依赖、事件驱动重绘（不动不画）。不选 Tauri：要带前端资源和 WebView 进程（每个 WebView2 进程几十 MB 内存）；不选 Slint：免费许可证要求展示其标识，egui 是 MIT/Apache |
| 进程模型 | 一个 exe，两种模式：**窗口模式**（打开界面）和**托盘守护模式**（只留一个检测线程，不建窗口、不加载渲染器）。关窗口 = 退回托盘守护，内存降到个位数 MB |
| 权限 | exe 清单要求管理员（改 HKLM、powercfg、进程优先级都需要）；开机自启用「任务计划程序 + 最高权限」，避免每次开机弹 UAC |
| 安装方式 | **单个签名 exe，下载即用**；首次运行提供「安装到本机」（复制到 `%LocalAppData%\Programs\LeanFPS`、开始菜单、开机自启、卸载项），也可保持便携 |
| 优化清单 | 数据驱动：`tweaks/*.toml` 编进 exe，每项含检测、应用、撤销、风险、依据链接、适用条件（台式机/笔记本、Win10/11、CPU/GPU 厂商）。格式参考 WinUtil 的 `tweaks.json`，但**应用前读取并保存真实旧值**（值原本不存在就记为 absent，撤销时删除），而不是像 WinUtil 那样恢复到写死的 Windows 默认值 |
| 默认配置原则 | 参考 Feral gamemode 与 PC-Tuning：「推荐」只开**游戏期间临时生效、退出自动还原**的项和少数低风险系统项；改注册表且需要重启、或依据不足的项放进「高级」，默认关闭，并提示用户先用内置测量对比 |
| 游戏库 | 内置游戏特征库（exe 名/路径 → 名称、类型、Steam appid），压缩后约 50–100 KB；可从我们的 CDN 下发签名更新 |
| 测量 | Rust 直接消费 ETW 的 Present 事件（不打包 PresentMon），算平均 FPS、1% low、帧时间波动 |
| 许可 | 账号制：网关账号 + 一次性商品；软件里点「解锁」→ 浏览器完成登录与付款 → 软件自动解锁。离线可用 30 天 |
| 退款 | **14 天无理由退款**（与 Radiant「售出不退」形成对比，$19 的退款成本很低）|
| 代码仓库 | 桌面软件放新的私有仓库 `Jamailar/leanfps`；官网放本仓库 `sites/leanfps/` |

## 4. 优化项（第一版约 25 项，宁少勿假）

分三层。「推荐」预设只开低风险、有机制依据的项；有安全代价的项永远不放进预设。

**A. 系统（一次性、持久，可逐项撤销）**
- 电源计划：台式机切高性能/卓越性能；笔记本只在接电源时切（插拔自动切回）。
- 关闭 CPU 核心休眠（core parking，电源计划子项）。
- 打开 Windows 游戏模式。
- 关闭后台录制（Game DVR / 游戏栏捕获）。
- 显卡硬件加速调度（HAGS）：只显示状态与建议，改动需重启并说明。
- 笔记本双显卡：为识别到的游戏写入「高性能 GPU」偏好（`HKCU\Software\Microsoft\DirectX\UserGpuPreferences`）。
- 关闭「提高指针精确度」（鼠标加速）——默认只在射击类专项里开。
- 游戏时的通知勿扰。
- 把识别到的游戏登记到 `HKCU\System\GameConfigStore`（PC-Tuning 提到的做法，让系统按游戏对待）。
- 高级（默认关）：MPO `OverlayTestMode=5`（只为闪烁/兼容问题）、Win32PrioritySeparation（24H2 取值映射已变，需要按系统版本处理）、Windows 11 的 `GlobalTimerResolutionRequests`（TimerResolution 作者说只建议用于调试，会增加所有进程开销，需要重启）。

**B. 游戏运行时（检测到游戏才应用，游戏退出自动还原）**
- 游戏进程优先级「高于正常」；受反作弊保护、打不开进程句柄的游戏，改用 IFEO `PerfOptions\CpuPriorityClass`（下次启动生效）。
- 关闭游戏进程的电源节流（EcoQoS，`ProcessPowerThrottling`），对混合架构 CPU/笔记本有意义。
- 后台常见占用（浏览器、启动器、同步盘、更新程序）降为「低于正常」优先级；游戏结束还原。
- 游戏期间暂停「传递优化」的后台下载带宽。
- 游戏期间阻止睡眠和屏保（`SetThreadExecutionState`，零风险）。
- 不做「后台请求计时器精度」：Win10 2004 起计时器精度只对调用它的进程生效（PC-Tuning、TimerResolution），我们的进程请求影响不到游戏，做了就是安慰剂。
- 可用内存低于阈值时清理待机列表（类 ISLC 做法，中风险，默认只在开放世界专项开）。

**C. 游戏类型专项（让用户看到「为它做的优化」）**

| 类型 | 例子 | 专项内容 |
| --- | --- | --- |
| 竞技射击 | CS2、Valorant、Apex、Fortnite、COD | 鼠标加速关、进程优先级、通知勿扰、电源节流关；提示打开游戏内 Reflex/Anti-Lag、限帧取刷新率整数倍并让 GPU 不跑满（PC-Tuning 有依据，只提示，不改游戏文件）|
| MOBA / RTS | LoL、Dota 2 | 核心休眠关、后台降级、电源节流关 |
| 开放世界 / 3A | Cyberpunk、GTA V | 待机内存清理、高性能 GPU 偏好、I/O 优先级、保留着色器缓存（不清）|
| 赛车 / 模拟 | Forza、iRacing | 帧时间稳定：电源计划、后台降级、勿扰 |
| 沙盒 | Minecraft Java（`javaw.exe`）| 为 `javaw.exe` 设高性能 GPU、优先级 |
| MMO / 网游 | WoW、FFXIV | 后台带宽限制、优先级 |
| 休闲 / 独立 | — | 笔记本均衡，不强推高功耗 |

**明确不做**（在官网写出来作为信任点）：关闭 Defender、关闭 HVCI/VBS、重置防火墙、停用 Windows 更新服务、关闭 Spectre 缓解、注入游戏、游戏内覆盖层、读写游戏内存或文件、「清理注册表」。

## 5. 游戏识别

1. **前台检测**：每 2 秒 `GetForegroundWindow` → 进程 exe 路径；窗口覆盖整个显示器（全屏/无边框）或该 exe 在游戏库目录里，就认定为游戏。几乎零开销，不依赖 WMI 事件。退出检测参照 gamemode：定期检查游戏 PID 是否存活，最后一个游戏退出后按相反顺序还原。
2. **匹配顺序**：内置特征库（exe 名 + 路径片段）→ Steam（`libraryfolders.vdf` + `appmanifest_*.acf`，用 `steamlocate` crate，MIT）→ Epic（`ProgramData\Epic\EpicGamesLauncher\Data\Manifests\*.item`）→ GOG/EA/Ubisoft/Battle.net/Riot 的注册表或已知路径 → 未知。
3. **类型**：**以内置特征库为主**。Steam 商店 `appdetails` 的 genres 太粗（实测 CS2 只返回 `Action, Free To Play`，没有「射击」），只作辅助，并且一次只能查一个 appid，结果本地缓存；仍未知就让用户选一次类型并记住。
4. **图标**：优先用 Steam 本地缓存的封面/图标（`appcache\librarycache`），否则从 exe 提取 256px 图标（`SHGetFileInfo`/`IShellItemImageFactory`），全部本地完成。
5. 首次打开时扫描已安装游戏，显示图标墙（「已发现 12 个游戏」）——这是第一次打开的惊喜时刻。

## 6. 测量（核心差异点）

- 用 `ferrisetw`（MIT/Apache）开 ETW 实时会话，订阅 Microsoft-Windows-DXGI 的 Present_Start（D3D10/11/12）和 D3D9 的 Present_Start，按游戏 PID 计算相邻 Present 的间隔（即 PresentMon 的 MsBetweenPresents） → 平均 FPS、1% low、0.1% low、帧时间标准差。只在游戏运行时开会话。
- **被动 A/B**：每局游戏自动记录（本地），按「同一游戏、优化前/后」对比；用户不用专门跑测试。也提供「60 秒基准」按钮。
- 结果卡片可复制成图片分享（转化与口碑）。
- 不显示覆盖层，避免反作弊风险。
- 第一版只测 CPU 侧的 Present 间隔，不关联 DxgKrnl 的 Flip（真正上屏时间，复杂度高）；Vulkan/OpenGL 游戏在界面上写明「暂不支持或不精确」。备选：随附 PresentMon 命令行（MIT），代价是体积增加。

## 10. 工程与发布

- 构建：GitHub Actions `windows-latest`，`cargo build --release`（`lto = "fat"`、`codegen-units = 1`、`panic = "abort"`、`strip = true`）；CI 里**卡体积**：exe > 8 MB 失败（硬上限 20 MB）。
- **自动化测试**：GitHub 的 Windows 虚拟机有管理员权限，可以对每一项优化跑「读原值 → 应用 → 校验 → 撤销 → 校验与原值一致」。真实游戏与显卡的测试需要实机。
- 性能预算（CI 或发布前测量）：冷启动 < 300 ms；窗口模式内存 < 60 MB；托盘守护 < 10 MB、CPU 平均 < 0.1%。
- 签名：见第 12 节。
- 发布：签名 exe → R2（版本化）→ 更新清单签名 → 官网下载链接更新。

## 14. 风险

- 实际帧数提升通常不大：靠测量说实话，不在官网写固定百分比。
- 反作弊：只改系统配置和进程优先级，不碰游戏进程内存；受保护进程改用 IFEO。上线前在 Valorant、CS2、Fortnite、Apex 实机验证不被拦。
- 杀软误报：签名 + 不打包驱动 + 不用加壳；发布后提交微软误报申诉通道。
- 签名证书资格（第 12 节）可能拖慢发布。
